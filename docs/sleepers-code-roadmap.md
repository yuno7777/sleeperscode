# Sleepers Code engineering roadmap

Canonical implementation tracker derived from `SLEEPERS CODE.md`. The repository and its tests are
the source of truth when this tracker and prose drift.

Status: `[ ]` pending, `[-]` in progress, `[x]` complete, `[!]` blocked, `[~]` deferred.

## Current milestone

The first Rust finite-process slice can be selected through persisted `runtimeBackend` settings or
debugging environment overrides. Current work hardens that boundary on Windows before provider
streaming or broader migrations. Node and Electron remain the default production path, and `auto`
stays on Node until Rust passes packaging and whole-application differential gates.

## Commit and release gates

- Create only substantive, reviewable commits; no empty commits or artificial history inflation.
- Keep phase changes isolated and preserve upstream mergeability.
- Do not push until the requested 150-200 new commits exist, focused validation passes, and staged
  content has been scanned for secrets.
- Publish no more than five GitHub releases. Releases require validated user-facing milestones,
  artifacts, checksums, notes, and rollback guidance; commits are not releases.
- Track new commits relative to upstream base `45d9aa90baab8f2d6b13c7ae3cf2f97128edaf7b`.
