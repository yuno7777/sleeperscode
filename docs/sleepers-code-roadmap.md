# Sleepers Code engineering roadmap

Canonical implementation tracker derived from `SLEEPERS CODE.md`. The repository and its tests are
the source of truth when this tracker and prose drift.

Status: `[ ]` pending, `[-]` in progress, `[x]` complete, `[!]` blocked, `[~]` deferred.

## Current milestone

The Rust sidecar now supports both bounded finite commands and opt-in byte-preserving streaming
sessions. Cursor and Grok route native ACP work through session-scoped sidecars while preserving
their Node wrapper fallback, and shared normalization bounds each provider event queue at 256 items.
The deterministic provider matrix passes under the supported Node toolchain. An interleaved
five-run, 10-session comparison reduced mean peak RSS by 21.2% with Rust while mean elapsed time
remained 2.1% slower on overlapping ranges, so Node and Electron remain the production default and
`auto` stays on Node while residual throughput, packaging, and whole-application differential gates
remain open.

Both concurrency and startup harnesses now alternate their variants inside a single invocation.
Measuring two backends as two separate runs produced a 1.2 second difference on this host that
disappeared on re-measurement, so any comparison taken that way is treated as unverified.

Phases 7, 8, and 9 were audited rather than implemented, and all three closed against their original
premise. Git's own work is not slow; the 38 ms process launch around it is, so native Git stays.
Filesystem traversal is already native and a plain Node walk with exclusions matches it, so nothing
migrates. No workspace file watcher exists at all, so Phase 8's storm protection has no target. ADR
005 generalises the rule these share: a component is migrated only once profiling implicates that
component, which is why Phase 11 is now blocked rather than pending.

## Commit and release gates

- Create only substantive, reviewable commits; no empty commits or artificial history inflation.
- Keep phase changes isolated and preserve upstream mergeability.
- Do not push until the requested 150-200 new commits exist, focused validation passes, and staged
  content has been scanned for secrets.
- Publish no more than five GitHub releases. Releases require validated user-facing milestones,
  artifacts, checksums, notes, and rollback guidance; commits are not releases.
- Track new commits relative to upstream base `45d9aa90baab8f2d6b13c7ae3cf2f97128edaf7b`.
