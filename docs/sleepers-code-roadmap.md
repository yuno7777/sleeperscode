# Sleepers Code engineering roadmap

Canonical implementation tracker derived from `SLEEPERS CODE.md`. The repository and its tests are
the source of truth when this tracker and prose drift.

Status: `[ ]` pending, `[-]` in progress, `[x]` complete, `[!]` blocked, `[~]` deferred.

## Current milestone

The Rust sidecar now supports both bounded finite commands and opt-in byte-preserving streaming
sessions. Cursor and Grok route native ACP work through session-scoped sidecars while preserving
their Node wrapper fallback, and shared normalization bounds each provider event queue at 256 items.
The deterministic provider matrix passes under the supported Node toolchain. An interleaved
five-run, 10-session comparison reduced mean peak RSS by 21.2% with Rust while mean elapsed time
remained 2.1% slower on overlapping ranges, so Node and Electron remain the production default and
`auto` stays on Node while residual throughput, packaged launch, and whole-application differential
gates remain open.

The ACP boundary test now fills all 256 normalized-event slots without a consumer on both backends,
uses the prompt response as a transport receipt, observes the exact queue depth, then attaches the
consumer and drains the blocked completion plus all 255 deltas losslessly. This closes the synthetic
queue-saturation gap without sleeps or polling; authenticated provider prompts and read-ahead memory
under real vendor transports remain open.

Both concurrency and startup harnesses now alternate their variants inside a single invocation.
Measuring two backends as two separate runs produced a 1.2 second difference on this host that
disappeared on re-measurement, so any comparison taken that way is treated as unverified.

Phases 7, 8, and 9 were audited rather than implemented, and all three closed against their original
premise. Git's own work is not slow; the 38 ms process launch around it is, so native Git stays.
Filesystem traversal is already native and a plain Node walk with exclusions matches it, so nothing
migrates. No workspace file watcher exists at all, so Phase 8's storm protection has no target. ADR
005 generalises the rule these share: a component is migrated only once profiling implicates that
component, which is why Phase 11 is now blocked rather than pending.

Phase 10 was the first of these audits to justify a code change: checkpoint capture discarded Git's
stat cache every turn, so a HEAD-stamped index cache took a 15,000-file capture from 24.6 s to under
a second, gated on tree-oid differential tests. Restore and diff stayed on native Git after measured
15,000-file means of 436.7 ms and 97.6 ms, with direct restore data-safety coverage. Phase 12's
abstraction turned out to already exist as a TypeScript driver SPI and does not depend on Phase 11;
what it lacked was capability negotiation. Phase 13 is complete for the built-in providers: none
scrapes terminal output, and every adapter now declares its integration transport.

Upstream through `1a003e383` is now merged. Its usage ledger, web dashboard, and mobile dashboard are
available in this fork and passed the merged focused validation. They provide real Claude/Codex token
and cost observations across environments, but they are not yet a task-outcome corpus and therefore
do not justify adaptive-router weights. Cursor, Grok, and OpenCode usage remain unmeasured.

Provider health checks now share a registry-owned scheduler and run one provider probe at a time.
The two-probe candidate still peaked at 1,161.8 MiB because Claude overlapped with OpenCode's two
internal discovery commands. Serializing providers reduced the directly paired peak by 28.9% to
825.6 MiB while settled RSS remained effectively unchanged; startup timing stayed inside the host's
known drift. OpenCode's internal parallel discovery is now the largest remaining startup transient.

Windows x64 packaging now produces a 153,933,897-byte Sleepers Code NSIS installer, blockmap, and
independently verified SHA-256 manifest. The retained artifact contains the pinned runtime dependency
set, Rust runtime sidecar, resource monitor, and a load-tested Linux x64 `node-pty` 1.1.0 prebuild for
WSL. Packaging is no longer blocked on artifact construction; it remains in progress until the
unsigned installer passes real launch, clean-machine, upgrade, and uninstall validation.

## Why 57 phases are blocked rather than pending

`[ ]` claimed these were merely unstarted, which was misleading: most cannot be started, and saying so
is more useful than a queue that implies otherwise. Each blocked phase falls into one of four classes,
and each class names what would actually unblock it.

**Needs a resource this environment does not have.** Phases 28, 54, 55, 91, 92, 99, 102. Code
signing needs a certificate; a clean-machine test needs a virtual machine; release
automation needs publishing rights; UI verification and desktop control need browser and computer use,
which require the developer's explicit permission per `AGENTS.md`. No amount of work here changes
these; they need someone to supply the resource.

**Needs evidence that does not exist yet.** Phases 32-36, 38, 43, 62, 64, 66, 67, 69, 70, 107. The
router, its scoring weights, its modes, and every analysis built on them depend on a corpus of real
task outcomes. `SLEEPERS CODE.md` is explicit that scoring must not be implemented as "fixed arbitrary
constants" and that telemetry must override assumptions. Building them now would mean inventing the
numbers the plan forbids inventing. They unblock when Phase 59's usage ledger has recorded real runs.

**Needs a subsystem that is not built.** Phases 14, 39-42, 44-53, 56-61, 63, 65, 71, 72, 74, 75, 79,
80, 87, 94, 106. Agent Arena needs agent collaboration, which needs task decomposition, which needs
the orchestration core. The tool bus is specified as Rust, which sits behind Phase 11. These are
ordinary dependency ordering, not obstacles.

**Needs a vendor artifact or live vendor state.** Phases 17, 18, 19, 23. Antigravity integration
cannot be verified without the CLI installed, and `SLEEPERS CODE.md` requires verifying its executable
name rather than assuming it. ADR 006 already moved install-fact verification for ACP agents onto the
publisher's own feed, which is the part of Phase 23 that could be solved without guessing.

Blocked is a status, not an abandonment: any of these resumes the moment its named condition holds.

## Commit and release gates

- Create only substantive, reviewable commits; no empty commits or artificial history inflation.
- Keep phase changes isolated and preserve upstream mergeability.
- Do not push until the requested 150-200 new commits exist, focused validation passes, and staged
  content has been scanned for secrets.
- Publish no more than five GitHub releases. Releases require validated user-facing milestones,
  artifacts, checksums, notes, and rollback guidance; commits are not releases.
- Track new commits relative to upstream base `45d9aa90baab8f2d6b13c7ae3cf2f97128edaf7b`.
